**Парсинг чужих прайсов звучит как задача на вечер. На практике это отдельная инженерная дисциплина: robots.txt, лимиты, диффы состояний, планировщик и способы не получить бан.**

Ниже — разбор системы, которая работает с сентября 2026: 6 источников, 33 ценовые позиции, ежедневная проверка, оповещения в Telegram. Сначала архитектура, потом то, что из неё получилось как побочный продукт.

## Зачем вообще это было

Причина банальная: **любой разговор о бюджете начинается с «ну это зависит»**. Продавец услуги всегда знает свою цену, покупатель — нет. Разрыв в 4–20 раз при прайде, который выглядит одинаково убедительно.

Чтобы получить честную картину, нужен был не «мой опыт», а сбор данных по чужим публичным прайсам. И нужен был сбор **повторяемый** — один раз посмотреть мало, рынок меняется.

## Архитектура

Всё умещается в три части.

**1. Сборщик.** Для каждого источника — свой адаптер. Адаптер возвращает простую структуру: источник, название услуги, цена, валюта, дата замера. Дальше общий код не знает, откуда пришли данные.

**2. Хранилище состояния.** JSON-файл вида:

```json
{
  "sources": {
    "zharkov": {
      "checked_at": "2026-10-02T13:58:53+00:00",
      "offers": [
        {
          "name": "Лендинг",
          "price": 150,
          "currency": "USD",
          "prev_price": 150,
          "change_pct": 0.0
        }
      ]
    }
  }
}
```

Ключевая деталь: **хранится не только текущая цена, но и предыдущая**. Без этого невозможно посчитать изменение.

**3. Дифф и алерт.** Скрипт сравнивает текущий срез с сохранённым, считает процент изменения и, если порог превышен, шлёт сообщение в Telegram.

Порог — **5%**. Почему не «любое изменение»: цены на сайтах constantly содержат шум — округления, «от» без числа, разная валюта. При нулевом пороге алерты превращаются в мусор, и через неделю их перестаёшь читать.

## Планировщик: почему GitHub Actions

Локальный cron работает, пока спит компьютер. Для ежедневной проверки это не подходит, поэтому всё уехало в GitHub Actions.

```yaml
on:
  schedule:
    - cron: "30 6 * * *"
```

Скрипт после сбора коммитит состояние обратно в репозиторий. Получается бесплатное хранилище истории без единой строчки инфраструктуры: диффы видны в git log, откат — обычный `git checkout`.

## Грабли, на которые наступил

### Локальный источник, который не проходит в CI

Один из источников отдаёт `403` на GitHub Actions, но открывается с домашнего интернета. Решение — флаг:

```json
{ "id": "pas7", "local_only": true }
```

В CI он пропускается, локально обходится. Счётчики источников в логе и в CI отличаются — это ожидаемо, и важно, чтобы это было **видно**, а не тихо.

### «Цена от» без числа

На части прайсов встречается конструкция «от 5 000 ₴» или «$350+». Это не цена, это витрина. Такие позиции помечены как требующие ручной проверки и не участвуют в расчёте медианы — иначе медиана смещается вниз.

### Валюты

Доллар, евро, гривна в одном срезе. Сравнивать напрямую бессмысленно, поэтому всё приводится к гривне по фиксированному курсу на дату среза. **Курс фиксируется явно и попадает в данные** — иначе через месяц нельзя понять, почему цифра изменилась.

### Сайт отдаёт цену только в вёрстке

Часть прайсов не имеет структурированных данных: цена лежит в карточке, собранной из пяти вложенных `div`. Кто-то бы написал регулярку по DOM. Это хрупко: одна перевёрстка ломает парсер молча, без ошибки, просто перестаёт приходить обновление.

## Что получилось

Данные — побочный продукт. Основной — сам факт, что рынок можно измерить, а не гадать о нём.

На момент среза картина такая:

- **лендинги: 3 700 – 15 000 ₴** (разброс 4×)
- **сайты: 12 300 – 75 000 ₴** (разброс 6×)
- **Telegram-боты: от 3 700 ₴**
- **парсинг: €150 за разовый сбор** — и ни одной позиции «мониторинг с алертами» ни у кого из шести

Последний пункт интереснее прочих. Разрыв в цене в 4–6 раз внутри одной категории — это нормально, качество на глаз не отличить. Но **пустое место на рынке** — это не разброс, это отсутствие предложения.

## Ограничение, о котором надо сказать честно

**Это снимок, а не тренд.** Одно измерение не доказывает направление рынка. Любой, кто делает выводы про «цены растут» по одному срезу, занимается гаданием.

Поэтому система сделана с расчётом на повторные замеры: когда накопится вторая и третья выборка, можно будет публиковать не прогноз, а фактические дельты — что было, что стало, кто оказался прав.

## Выводы

Парсинг прайсов — это не «открыл страницу и вытащил текст». Это поддержка состояния, работа с шумом, вежливость к чужой инфраструктуре и постоянный вопрос «а не сломалось ли моё молча».

Если вам кажется, что на рынке «все всё знают» — скорее всего, нет. Большинство прайсов просто никто не сверяет между собой. Иногда достаточно написать 300 строк кода, чтобы получить цифры вместо ощущений.
