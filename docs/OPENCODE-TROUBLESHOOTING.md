# OpenCode: типичные ошибки, как чинить, как перезагрузжать

Единая памятка. Собрана 03.10.2026 из двух ранее существовавших файлов
(`opencode-errors-guide.md` и `OPENCODE-GUIDE.md`) — они больше не нужны,
всё нужное здесь.

**Про секреты:** в этой версии нет ни одного ключа, токена или пароля
открытым текстом. Все места хранения указаны в разделе 5.

---

## 0. Главное

OpenCode — терминальная программа. Она **не ломается навсегда**: любая ошибка
либо лечится за 1–5 минут, либо уходит после перезапуска.

**Проделанная работа не теряется.** Коммиты уже на GitHub, правки остаются
в файлах на диске. Перезагрузка компа — не откат проекта.

Если что-то пошло не так, достаточно описать своими словами по схеме:
> делал вот что → увидел вот это → ожидал вот это

Этого хватает в 90% случаев. Технические названия ошибок знать не нужно.

## 1. ПЕРЕЗАГРУЗКА

### 1.1 Быстрое переключение сессии (в TUI)

| Команда | Что делает | Горячая клавиша |
|---|---|---|
| `/new` | Новая сессия с нуля (алиас `/clear`) | `ctrl+x n` |
| `/sessions` | Список и переключение сессий (`/resume`, `/continue`) | `ctrl+x l` |
| `/compact` | Сжать контекст сессии (`/summarize`) | `ctrl+x c` |
| `/undo` | Отменить последнее сообщение **и все изменения файлов** | `ctrl+x u` |
| `/redo` | Вернуть отменённое (после `/undo`) | `ctrl+x r` |
| `/exit` | Выйти (`/quit`, `/q`) | `ctrl+x q` |
| `/export` | Выгрузить диалог в Markdown и открыть в редакторе | `ctrl+x x` |
| `/help` | Список команд | — |
| `/init` | Создать/обновить `AGENTS.md` | — |

Leader-клавиша по умолчанию — `ctrl+x`, ждёт 2000 мс. Меняется в `tui.json`
через `leader_timeout`.

**Важно:** `/undo` и `/redo` работают через Git. Проекту **обязательно** нужен
git-репозиторий, иначе отмена файлов не сработает.

### 1.2 Полная перезагрузка (самое частое)

Самый надёжный способ при странном поведении:

```
/exit
```

затем в терминале:

```
opencode
```

Открыть сразу другую папку:

```
opencode C:\Users\Admin\Documents\site
```

### 1.3 Пошагово для новичка

1. Закрой окно терминала крестиком или нажми `Ctrl+C`.
   `Ctrl+C` — это остановка текущей команды, **НЕ поломка**.
2. Открой PowerShell: Пуск → набери `powershell` → Enter.
3. Набери `opencode` → Enter.
4. Сессия продолжается сама: мысли и план сохраняются в `AGENTS.md` и истории на диске.
5. Если экран пустой и кажется, что началось с нуля — напиши
   «продолжай, было вот что: …» и коротко опиши задачу.
6. Если терминал не открывается или нет ответа дольше 5 минут —
   перезагрузка компа (крайний случай), затем `opencode` заново.

⚠️ Ни один шаг **не теряет** твою работу.

### 1.4 Если сломалось — по возрастанию тяжести

1. **Плагины виноваты.** В `%USERPROFILE%\.config\opencode\opencode.jsonc`
   поставить `"plugin": []`. Если поле уже было — дописать. Перезапустить.
2. **Папки с плагинами.** Временно переименовать
   `%USERPROFILE%\.config\opencode\plugins` и `<проект>\.opencode\plugins`.
3. **Кэш провайдеров.** Закрыть приложение, удалить
   `%USERPROFILE%\.cache\opencode`, запустить заново — пакеты провайдеров
   переустановятся свежими. Это чинит большую часть `AI_APICallError`
   и ошибок после обновления моделей у провайдера.
4. **Хранилище.** Удалить `%USERPROFILE%\.local\share\opencode`, затем
   `/connect` заново. **Теряет все сессии и `auth.json`** — последнее средство.
5. **Обновить:** `opencode upgrade`

### 1.5 Частые ошибки запуска

| Симптом | Причина и решение |
|---|---|
| Не запускается | `opencode --print-logs` → смотреть лог; `opencode upgrade` |
| Не пройден вход | `/connect` в TUI; проверить ключ и доступ к API провайдера |
| `Model not available` | Модель указана неверно. Формат `<providerId>/<modelId>`, например `openai/gpt-4.1`. Список: `opencode models` |
| `ProviderModelNotFoundError` | То же — неправильная ссылка на модель |
| `ProviderInitError` | Битый конфиг провайдера. Починить по `/docs/providers`, иначе удалить `%USERPROFILE%\.local\share\opencode` и снова `/connect` |
| `AI_APICallError` | Устарел кэш пакетов провайдера → удалить `%USERPROFILE%\.cache\opencode`, перезапустить |
| Desktop: «Connection Failed» | Проверить, не задан ли свой URL сервера. На Home нажать на имя сервера → Clear. Убрать секцию `server` из `opencode.json`, снять переменную `OPENCODE_PORT` |
| Desktop: белое окно | Нужен Microsoft Edge **WebView2 Runtime** — установить/обновить |
| Desktop: тормоза на Windows | Попробовать WSL — окружение Linux работает ровнее |
| Desktop: не приходят уведомления | Включены в ОС **и** окно не в фокусе. В TUI: `tui.json` → `attention.enabled: true` |

### 1.6 Диагностика

```
opencode --print-logs          подробный вывод в терминал
opencode --log-level DEBUG     уровень логов
```

Логи (Windows): `WIN+R` → `%USERPROFILE%\.local\share\opencode\log`
Хранилище сессий и ключей: `%USERPROFILE%\.local\share\opencode`

Если поведение странное и непонятно, что сломалось: `/export` — диалог
выгрузится в Markdown, можно прочитать целиком и понять, где поехало.

## 2. Ошибки самого OpenCode

### 2.0 Что реально встречается

Пересчитано по логу 03.10.2026 (103 640 строк, июнь–октябрь):

| Что в логе | Кол-во | Это ошибка? |
|---|---|---|
| `permission` | 22 240 | ❌ Нет, это журнал разрешений |
| Timeout | 407 | Команда дольше лимита |
| `AI_APICall` | 350 | Провайдер/ключ/модель не отвечают |
| `429` | 178 | Лимит запросов исчерпан |
| `models.dev` / `fetch failed` | 58 / 57 | Нет сети до сервера моделей |
| `Unauthorized` | 34 | Ключ отозван или опечатка (401) |
| `ByteString` | 33 | Не-ASCII символ в заголовке |
| `Abort` / `terminated` | 11 / 5 | Пользователь нажал Ctrl+C — **не ошибка** |

Вывод: 22 тысячи «ошибок» — это норма. Реальные проблемы — timeout и сеть.

### 2.1 «Cannot convert argument to a ByteString ... value of 1089»

**Симптом:** программа отвечает ошибкой `ByteString`, значение больше 255.

**Причина:** в ключ затесался не-ASCII символ. 1089 — это кириллическая
«с», визуально неотличимая от латинской «c». Заголовки HTTP по спецификации —
байты до 255, поэтому программа падает.

⚠️ **Это НЕ про «жив/мёртв ключ».** Стек ошибки показывает `new Headers` /
`webidl.converters.ByteString` — падение происходит **локально, ДО** отправки
запроса на сервер. Сервер про ключ вообще не узнаёт.

**Как отличить от п.2.2:**
- `ByteString` с кодом >255 → не-ASCII символ в ключе/заголовке.
  Чистый ASCII-ключ такую ошибку дать не может.
- `Invalid API key` / `Unauthorized` → это 401, сервер ключ не признал.
  **Это разные вещи, не путать.**

**Проверка ключа на не-ASCII** (вставь в PowerShell, работает сразу):

```powershell
$raw = [System.IO.File]::ReadAllText("$env:USERPROFILE\.local\share\opencode\auth.json")
$bad = 0..($raw.Length-1) | Where-Object { [int]$raw[$_] -gt 127 }
if ($bad) { $bad | ForEach-Object { "позиция $($_+1): код $([int]$raw[$_])" } }
else { "OK: только ASCII" }
```

Если позиции нашлись — ключ надо заменить.

### 2.2 «Invalid API key» / «Unauthorized» (401)

**Причина:** ключ отозван, ротирован, либо введён с опечаткой или лишним пробелом.

**Что делать:**
1. **НЕ менять ключи по памяти.** Сверить два файла —
   `auth.json` и `account.json` в `%USERPROFILE%\.local\share\opencode\`.
   Оба должны содержать один и тот же рабочий ключ `sk-1M8X…`.
2. Проверить ASCII по команде из п.2.1.
3. Обновить ключ (менять только текст ключа, структуру JSON не трогать).
4. Перезапустить OpenCode (раздел 1).

**Важно про эту среду:** рабочий ключ OpenCode **один**. Ключи, которые
начинаются на `X6ruf1e9…` и `2KyEJeS7v…` — это ключи **Dev.to**, для OpenCode
они никогда не работали (401). Их отзыв на OpenCode не влияет, они нужны
только для статистики Dev.to. Ошибки 24–25.09 были как раз потому, что в
`auth.json` лежал Dev.to-ключ.

Проверка живости ключа (ожидаем **403 FreeTier**, а не 401 — значит сервер
ключ узнал):

```
curl.exe -s -o NUL -w "%{http_code}" -X POST https://opencode.ai/zen/v1/chat/completions -H "Content-Type: application/json" -H "Authorization: Bearer $env:OPENCODE_KEY" -d "{\"model\":\"big-pickle\",\"messages\":[{\"role\":\"user\",\"content\":\"ping\"}]}"
```

### 2.3 Rate limit (429)

**Причина:** лимит запросов за период исчерпан.

**Что делать:** подождать ~1 минуту — лимиты обычно по минуте/часу.
Если повторяется регулярно — разнести действия по времени.

### 2.4 Команда молчит / долго висит / timeout

**Причина:** деплой, GitHub Actions или обход сайта работают дольше
дефолтных 120 секунд.

**Что делать:** сказать «запусти ещё раз с бо́льшим ожиданием».
Ничего не чинить параллельно самому.

### 2.5 Сетевые ошибки (fetch failed, models.dev)

**Что делать:** включить VPN. Для GitHub, Dev.to, Google и GSC OpenCode
работает и без VPN.

### 2.6 «oldString not found» при правке файла

**Причина:** файл открыт или изменён руками либо в другом окне —
содержимое разошлось с тем, что ожидала правка.

**Что делать:** сказать «перечитай файл и повтори правку».
Файл будет перечитан и правка применена заново.

### 2.7 Зависший процесс / нет ответа совсем

1. Подождать 2–3 минуты (идёт деплой).
2. `Ctrl+C` — прерывает текущую команду, ничего не ломает.
3. Перезапустить OpenCode (раздел 1).
4. Если терминал не открывается — перезагрузка компа, крайний случай.

## 3. Ошибки уровня проекта

### 3.1 Главное правило

`AGENTS.md` в корне проекта — закон. В нашем проекте: **ничего не менять без
явного разрешения**. Слово «делай» даётся на конкретный пакет задач, не на всё
подряд.

### 3.2 Выдуманные данные — самая дорогая ошибка

Реальные случаи из этого проекта:

1. В заголовке статьи про цены было «33 000 просмотров на vc.ru». На деле —
   616. Заголовок уехал в заготовку для Хабра.
2. В таблицах статей были названия услуг, которых нет на сайтах студий:
   у Web24 в прайсе `БЮДЖЕТНЫЙ / СРЕДНИЙ / ПРЕМИУМ САЙТ`, а в статье —
   «Сайт на CMS», «Сайт-портфолио». У SUDUS в данных `Стоимость 23 000`,
   в статье — «Сайт-каталог».

**Как правильно:** любое число и любое название, которое пойдёт в публикацию,
сверять с первоисточником. Данные — в `parser/state.json`, выгрузка
сверяется покомпонтно.

То же про выводы по аналитике: два визита на `/articles.html` — это не
«почти наверняка вы». В API нет IP посетителей, идентифицировать нельзя.

**Проверка гипотез, а не выдумывание причин.** Пример из 03.10: `page = "unknown"`
у всех 6 заявок выглядел как поломка. На деле атрибуция появилась 29.09
(коммит `63d77a5`), а все заявки датированы 29.08–19.09 — то есть **до** её
появления. Это исторические данные. Сначала `git log -S`, потом выводы.

### 3.3 Git

- **Сначала `git pull --rebase`.** Remote регулярно уходит вперёд (workflow
  делают коммиты сами), и push падает с rejection.
- Пушить через `git push origin main` **работает** (проверено 03.10, три
  коммита подряд). Ранее в гайде было написано обратное — это устарело.
- Не коммитить чужие untracked-файлы. Перед `git add` всегда смотреть
  `git status --short` и добавлять поимённо.
- Список untracked, который нельзя трогать, зафиксирован в `AGENTS.md`.
- При конфликте rebase **не** использовать `git checkout --ours`: это
  молча берёт чужую версию. Так однажды потерялись 21 цена из
  `parser/state.json`. Правильно: прочитать конфликт и решить руками.
- Фраза «репозиторий чистый» может быть неверной: tracked синхронизированы,
  но untracked лежат. Признать и исправить, а не игнорировать.

### 3.4 PowerShell 5.1 (оболочка этого проекта)

| Проблема | Решение |
|---|---|
| Нет `&&` | `cmd1; if ($?) { cmd2 }` |
| Кракозябры вместо кириллицы | Не печатать в консоль. Писать в файл и читать через `read` |
| Python падает на `UnicodeEncodeError: cp1251` | `$env:PYTHONIOENCODING='utf-8'` перед запуском |
| Обрезанный вывод | Не использовать `Select-Object -First/-Last` — вывод и так пишется в файл целиком |
| Смена каталога | Не делать `cd` внутри команды, а передавать `workdir` |
| Чтение файлов | Не через `Get-Content`, а через инструмент `read` |
| Битые символы в файлах | Писать через Python `Path.write_text(..., encoding='utf-8')` |

### 3.5 Сеть и API — состояние на 03.10.2026

| Ресурс | С компьютера | Примечание |
|---|---|---|
| GitHub | ✅ | — |
| Google, GSC API | ✅ | Ранее в гайде было «Украина блокирует Google» — **устарело** |
| dev.to и `dev.to/api` | ✅ | — |
| `api.dev.to` | ❌ | Поддомен не резолвится. Использовать `dev.to/api` |
| Yandex / Яндекс.Метрика | ❌ | DNS резолвится, HTTPS не проходит. **На телефоне работает** |
| vc.ru | ❌ | DNS-блок. Только ручная публикация с VPN |
| Medium | ❌ | 403 без браузера, автопубликация невозможна |

- **Dev.to API отдаёт 403 на `urllib` без User-Agent.** С `requests` или
  браузерным UA — 200. Это **не** «ключ невалидный». Не перевыпускать ключ.
- `curl` из PowerShell даёт 403 на некоторые API. Использовать Python `requests`.
- **PAS7 Studio** отдаёт 403 из CI — помечен `local_only` в `parser/sources.json`,
  запускается только локально.
- Не обходить авторизацию и не делать аккаунты ради обхода ограничений площадки.

### 3.6 Секреты

- **Никогда не вставлять ключи, PAT, seed-фразы, cookies в чат и в файлы
  документации.** Ввод — во временный файл, использовать, **удалять сразу после**.
- Гайды и заметки хранятся **вне репозитория** либо в `docs/`, но секретов
  в них быть не должно.
- Проверенный endpoint обновления секретов GitHub
  `/repos/<owner>/<repo>/sealed-box/public_key` отдаёт 404; `gh` CLI и пакет
  `sealed_box` не установлены. Отсутствие инструментов — не доказательство
  невозможности: стандартный `/actions/secrets/public-key` не проверялся.

### 3.7 Парсер цен

Состояние на 03.10.2026: 6 источников, **54 цены**
(8 + 2 + 8 + 8 + 25 + 3), 0 проблемных подписей.

⚠️ **Парсер молчит, даже когда собирает мусор.** «0 изменений выше порога»
означает «совпало с прошлым значением мусора», а не «всё в порядке».
После правки селекторов обязательно сверять `state.json` с реальным прайсом.

Типичные порчи названий (парсер берёт текст вокруг цены, а не название услуги):

| Источник | Что попадает в `label` | Что нужно |
|---|---|---|
| SUDUS | `Стоимость` — селектор `td:first-child` не в ту ячейку | имена в `.tz-tier` |
| Web-Lift | `Термін: 5 робочих днів` — это срок | имена в `.wl-rel-card` |
| PAS7 Studio | описание вместо названия | брать заголовок, а не description |

Также: `state.json` недоступен извне (404 — это ожидаемо, он для внутреннего
хранения). Наружу отдаётся `parser/report.html`.

### 3.8 Площадки

- **Хабр:** 3 отказа подряд (08.09, 10.09, 15.09). Причины — самопиар и формат
  списка. Направление закрыто.
- **vc.ru:** без Pro посты не индексируются, лимит 1 пост в месяц. Путь:
  письмо на `moderation@vc.ru`, второй аккаунт не заводить.
- **Medium:** автопубликация невозможна — нет Integration Token, только ручная
  вставка. Приоритет невысокий, 0 подписчиков.
- **Dev.to:** единственная площадка с рабочим автопостингом.
  Опубликованную статью текущим create-only workflow обновить нельзя.

### 3.9 Проверка результата

- HTTP 200 на своём запросе **не означает**, что запрос засчитан в аналитику.
  Проверка с машины не выполняет JS-пиксель и не попадает в счётчик.
- Проверять `/pixel`, а не `/api/pixel` — несуществующий путь даёт 404
  и выглядит как поломка.
- `GET` к POST-эндпоинту отдаёт 405 — это нормально, не ошибка.
- Перед тем как объявить что-то сломанным, проверить, не появилось ли это
  только что: `git log --oneline -10` и `git log -S "<строка>"`.

## 4. Порядок диагностики

Если непонятно, что сломалось, идти сверху вниз:

1. **Перезагрузить** (раздел 1). Часто этого достаточно.
2. **Сеть** — VPN включён? (п.3.5)
3. **Ключи** — 401? Два файла с ключом совпадают? ASCII? (п.2.1, п.2.2)
4. **Права на файл** — открыт ли файл в другом редакторе? (п.2.6)
5. **Порядок коммитов** — remote впереди? (п.3.3)
6. **Таймаут команды** — просто подождать или повторить с большим ожиданием. (п.2.4)
7. **Кэш провайдеров** — `%USERPROFILE%\.cache\opencode` (п.1.4)
